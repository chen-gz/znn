## 🎯 目标与背景 (Context & Motivation)

在目前的 `znn` 架构中：
1. **CPU 级 SIMD / AMX / Accelerate 加速**已在编译期根据目标平台（Apple Accelerate, ARM64 NEON, x86 AVX2/AVX-512, FMA）通过 `src/backend/target.zig`、`cblas.zig` 与 `vec_math.zig` 实现了全自动识别与链接；
2. **GPU 级硬件加速（Apple Silicon Metal / NVIDIA CUDA）**虽已在底层 `src/backend/device.zig` 中具备探测逻辑，但前端默认配置 `GraphOptions.device` 硬编码为 `.cpu`，导致用户必须显式传递 `.{ .device = .metal }` 或 `.{ .device = .cuda }` 才能启用硬件加速；
3. **混合执行与回退短板**：若计算图开启 GPU 运行，一旦遇到尚未移植到 GPU 的算子（如 `sub`、`div`、`relu`、`sigmoid`、`gather` 等），或遇到直接读取 `tensor.data[0]` 的场景，容易因 GPU 张量 `data` 为空未同步而导致越界崩溃或执行错误。

**本里程碑核心任务**：
彻底打通**零配置自适应硬件识别与加速分发**，用户或上层调用者在初始化模型或计算图时**无需任何显式硬件参数**，底层自动探测并分派最优加速环境；同时构建**统一内存零拷贝与透明 CPU 回退机制**，确保任何算子与数据读取在全自动加速下均 100% 稳定运行。

## 🛠️ 修改清单与技术契约 (Modification Inventory & Contracts)

### 1. 前端零配置默认设备适配 (`src/backend/device.zig`, `src/autodiff/graph.zig`, `src/models/*.zig`)
- **`Device.defaultOptions()` / `defaultDevice()` 升级**：
  - 结合编译期内省与运行期驱动检测，确定首选计算设备优先级：`Metal (Apple Silicon) > CUDA (NVIDIA) > CPU (SIMD/AMX/Accelerate)`；
  - `Device` 结构体默认字段改为自适应初始值：`pub const Device = struct { type: DeviceType = defaultDevice().type, index: u32 = defaultDevice().index, ... }`；
  - `GraphOptions.device: Device = Device.defaultOptions()`，使得 `Graph.init(allocator, .{})` 默认即可开箱即用最优硬件加速；
  - 同步更新 `models.GPT.Config`、`models.Gemma4*` 等模型配置的默认设备为 `Device.defaultOptions()`。

### 2. Apple Silicon 统一内存架构 (UMA) 零拷贝桥接 (`src/autodiff/ops.zig`)
- 在 Apple Silicon Metal / MLX 下，CPU 与 GPU 物理共享同一片 DRAM：
  - 在 `ops.storeMlxOutput` 中，利用 `res_mlx.dataFloat32()` 接口在行主序连续时直接将求值后的浮点切片赋给 `out.data`（借用被 `out.storage` 长期持有的 MLX 显存句柄）；
  - 消除昂贵的额外主机 staging 复制，使计算图输出在 Metal 上计算后，其 `out.data[0]`、切片读写与下游 CPU 算子可以直接**零拷贝访问**。

### 3. 透明 CPU 回退与混合调度引擎 (`src/autodiff/graph.zig`, `src/autodiff/graph_nn.zig`)
- 在 `Graph` 中增加 `ensureHost(t: *Tensor) !void` 守卫：
  - 当非 GPU 算子（如 `sub`, `div`, `relu`, `sigmoid`, `tanh`, `silu`, `exp`, `log`, `sqrt`, `pow`, `sum`, `mean`, `gather`, `scatter`, `scatterAdd`, `indexSelect` 等）执行时，自动检测输入张量是否在 GPU 上但宿主数据尚未就绪；若尚未就绪，通过 `t.syncHost(self.arena.allocator())` 自动同步至主机；
  - 随后分派至 CPU SIMD / Accelerate 高速内核；
  - 当下游算子需要 GPU 输入时，`ops.borrowMlxArray` / `borrowCudaArray` 自动将宿主数据无损提升（Promote）回 GPU。
- 在 `registerSingleOutputOp` 中，梯度切片分配必须以 `C.shape.totalElements()` 为准，杜绝任何因 `C.data.len == 0` 分配空梯度缓冲区的隐患。

### 4. 宿主数据访问与标量提取标准协议 (`src/tensor/core.zig`, `src/tensor/tensor.zig`)
- 扩展 `Tensor` 的公共便捷方法：
  - `pub fn item(self: *Tensor, allocator: ?std.mem.Allocator) !f32`：对标 PyTorch `x.item()`，自动确保宿主同步并安全返回单元素标量值；
  - `pub fn toHost(self: *Tensor, allocator: ?std.mem.Allocator) ![]const f32`：自动同步并返回宿主只读数据切片。

### 5. 硬件内省与摘要工具 (`src/backend/device.zig`, `src/backend.zig`)
- 暴露 `backend.accelerationSummary(allocator: std.mem.Allocator) ![]const u8`：
  输出紧凑、规范的底层加速详情（如 `[znn-hardware] Device: metal:0 | Accelerators: MLX, Accelerate(AMX/NEON) | SIMD: 128-bit`）。
